# Формат патчей семантического графа

Патч задаёт упорядоченные изменения одного графа. Правила идентификаторов, допустимых атрибутов, ссылочной целостности и ревизий определены в [формате DOT](dot-storage.md). Формат ниже предварительный: состав атрибутов и смысл фактов нужно согласовать с ещё отсутствующими спецификациями семантической модели и контрактов LLM.

## Представление

Патч — JSON-объект с обязательными полями `base_revision` (неотрицательное целое) и `operations` (непустой массив объектов). `base_revision` должен совпадать с ревизией исходного графа; иначе патч отклоняется. Все имена полей чувствительны к регистру, неизвестные и повторяющиеся поля отклоняются. Все идентификаторы — строки, соответствующие `[A-Za-z][A-Za-z0-9_-]*`; пространства узлов и связей раздельны. JSON кодируется в UTF-8.

Каждая операция содержит строковое поле `op` и ровно поля из таблицы. `id`, `source`, `target` — идентификаторы; `label` — непустая строка Unicode. `attributes` — непустой объект обновляемых атрибутов: пока допустим только `label`. Отсутствующие атрибуты остаются без изменений; `null` и пустое значение недопустимы. ID и концы существующей связи неизменяемы; для изменения концов нужны удаление старой связи и добавление новой с другим ID.

| `op` | Обязательные поля кроме `op` | Действие |
|---|---|---|
| `add_node` | `id`, `label` | Добавить узел с новым ID. |
| `update_node` | `id`, `attributes` | Изменить атрибуты существующего узла. |
| `delete_node` | `id` | Удалить существующий узел без инцидентных связей. |
| `add_edge` | `id`, `source`, `target`, `label` | Добавить связь с новым ID между существующими узлами. |
| `update_edge` | `id`, `attributes` | Изменить атрибуты существующей связи. |
| `delete_edge` | `id` | Удалить существующую связь. |

## Порядок и проверка

1. Проверить JSON, структуру, типы, обязательные поля, имена операций и идентификаторы; проверить ревизию исходного графа.
2. Проверять операции по порядку относительно исходного графа с учётом результатов предыдущих операций. Новые ID должны быть свободны; изменяемые и удаляемые объекты должны существовать. Концы добавляемой связи должны существовать к моменту операции.
3. Применять операции последовательно к независимой копии. Один объект каждого вида может быть целью только одной операции в патче: повторное добавление, обновление или удаление того же ID считается конфликтом. Ссылки на узел в операциях со связями не считаются операциями над узлом.
4. Удаление узла допускается только после удаления всех его инцидентных связей предыдущими операциями того же патча. Неявного каскадного удаления нет. Для добавления связи новые узлы сначала объявляются операциями `add_node`.
5. Проверить итоговый граф по правилам DOT и согласованной семантической модели: уникальность ID, допустимость атрибутов и наличие обоих концов каждой связи. При ошибке сообщить индекс операции (начиная с нуля), объект и причину, а для общей ошибки — причину без индекса.

Патч атомарен: при любой ошибке исходный граф и его файл остаются без изменений; частичные результаты копии не публикуются. Только после успешной итоговой проверки результат сохраняется целиком. При фактическом изменении графа новая ревизия на единицу больше исходной; при отсутствии изменения ревизия сохраняется. Атомарная замена файла и обнаружение конкурентной записи относятся к будущему хранилищу и должны обеспечивать эту гарантию также при ошибке сохранения.

## Объяснение изменений

Для успешного патча следует сохранить порядок операций, ID затронутых узлов и связей, старые и новые значения изменённых атрибутов, данные добавленных и удалённых объектов с концами связей, а также исходную и итоговую ревизии. При наличии источника входного сообщения можно сохранить ссылку на него. Эти сведения позволяют объяснить изменения; способ хранения истории и источников требует отдельного согласования. Отклонённый патч не записывает изменения графа.

## Примеры

Каждый пример применяется отдельно к [исходному графу](../examples/dot/valid.dot), ревизия которого равна `0`.

- [Добавление факта](../examples/patches/add-fact.json): новый узел и связь с ним.
- [Изменение факта](../examples/patches/update-fact.json): изменение названия существующей связи.
- [Удаление ошибочной связи](../examples/patches/delete-edge.json).
- [Некорректный патч](../examples/patches/invalid-missing-node.json): конец связи не существует, поэтому весь патч отклоняется.

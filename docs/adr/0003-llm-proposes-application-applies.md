# ADR-0003. LLM предлагает изменения, приложение проверяет и применяет

- **Статус:** Принято
- **Дата:** 2026-11-04

## Контекст

LLM полезна для извлечения знаний, классификации намерений и генерации ответов, но её выводы вероятностны и могут содержать вымышленные факты, неверные идентификаторы или синтаксически некорректные данные. Прямая запись ответа модели в DOT-файл сделала бы состояние модели непредсказуемым.

## Решение

LLM возвращает только структурированные предложения в JSON, проверяемые по схеме. Python-код преобразует их в операции `GraphPatch`, проверяет патч относительно текущего графа и применяет его к копии. Модель не получает права записи в файл и не формирует DOT напрямую.

Промпты разделяют системную инструкцию и пользовательские данные; пользовательский текст рассматривается как данные, а не как команда. Ответ на вопрос строится только по переданному подграфу; при недостатке контекста система сообщает об этом.

## Последствия

- Детерминированная часть системы контролирует целостность модели.
- Ошибки модели проявляются как отклонённый патч с диагностикой, а не как повреждение файла.
- Требуются схемы ответов, валидация JSON и тестовая реализация LLM.
- Часть естественно-языковых изменений может требовать уточнения, если модель вернула неполные данные.

## Рассмотренные альтернативы

- **Разрешить LLM редактировать DOT.** Проще реализовать, но невозможно гарантировать инварианты и воспроизводимость.
- **Полностью детерминированное извлечение без LLM.** Не покрывает свободный текст и противоречит цели проекта.
- **Доверять ответу LLM без проверки схемы.** Снижает надёжность и усложняет диагностику.
